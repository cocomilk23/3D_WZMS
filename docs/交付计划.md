## 交付节奏

- 每完成一个可独立检查的建模或工具工作单元，提交并推送 Git；每次工作会话结束前保存本轮已验证进展。
- 下面的阶段完成后建立版本标签，交付说明包含改动、文件入口、截图或预览、核验方法、已知缺口和下一阶段内容。
- 模型阶段必须附有可打开的模型和视觉预览；报告或脚本不能充当已完成的校园模型。
- 中间结果可以交付，但必须标明“体块”“样板”“未校准”等实际状态。
- 不预设日历自动运行或固定完工日期；这里的周期按实际工作单元和里程碑执行。

## 文件与大素材

项目文档、脚本、全景配置、索引、校验清单使用普通 Git。Blender、FBX、GLB 和 UE 二进制资产使用 Git LFS。自动缓存、备份和打包产物不提交。

95 份全景切片包及完整派生高清图库目前保存在本机，不上传普通 Git。具体模型所需的参考图可打包进对应 Blender 文件，通过 LFS 管理；v0.0.2 已打包一张南大门正面参考图。完整来源和哈希记录在 `reference/reports/`；仅克隆仓库不会获得全量高清全景。后续异地交付完整素材库时，另建素材包传输与验收记录，不声称 Git 已备份完整图库。

本仓库使用项目级提交身份 Codex <codex@localhost>，不修改电脑的全局 Git 身份。
